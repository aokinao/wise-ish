# App内課金の設定手順

「言葉の棚」の買い切り課金を App Store Connect に登録する手順です。
2026-08-31 に一度作成したものを誤って削除し、製品IDを使えなくした経緯があるため、
同じ失敗を繰り返さないよう手順として残します。

## 最初に：絶対にやってはいけないこと

**作成した App内課金を削除しないでください。**

Apple は、一度使った製品IDを削除後も恒久的に予約します。削除すると**同じ製品IDで作り直すことは
二度とできません**。復元も、原則としてできません（Apple Developer Support に依頼して対応して
もらえる場合はありますが、確約は無く数日かかります）。

作成をやり直したくなった場合は、削除ではなく**内容の修正**で対応してください。
価格、表示名、説明、スクリーンショットは、審査提出前ならいつでも変更できます。

## 手順

### 0. 有料App契約を先に済ませる

**ここが未完了だと、以下を全部やっても商品情報はアプリに降ってきません。**
初回リリースで課金が動かない原因の最頻出パターンです。

App Store Connect →「ビジネス」（契約/税金/口座情報）で確認する。

- [ ] **有料App契約**のステータスが「有効」
- [ ] 銀行口座情報が登録・承認済み
- [ ] 税務フォームが提出済み

審査提出とは独立した手続きで、承認まで数日かかることがあります。

### 1. App内課金を作成

マイApp →「Wise-ish」→ サイドバー「収益化」→「App内課金」→ ＋

- [ ] タイプ：**非消耗型**
- [ ] 参照名：`言葉の棚`（社内管理用。ユーザーには見えない）
- [ ] 製品ID：`com.naoki.Wiseish.wordshelf` をコピーして貼り付け

製品IDは作成後に変更できません。保存前に一文字ずつ確認してください。

### 2. 価格

- [ ] 基準国を**日本**にして **¥500** を選ぶ
- [ ] 他国の価格は自動換算のまま

### 3. App Store情報（ローカリゼーション）

日本語を追加する。

- [ ] 表示名：`言葉の棚`（30字以内）
- [ ] 説明：`Ishがこれまで置いてきた言葉を、いつでも読み返せます。言葉の棚をひらきます。`（45字以内。この文面は39字）

### 4. 審査に関する情報

**ここの記入漏れが最も詰まりやすい箇所です。**

- [ ] **スクリーンショット（必須）**：`docs/assets/appstore/iap-review-640x920.png` を使う。
      **これが無いと永久に「メタデータ不足」のままで、TestFlight でも商品が取得できません**
- [ ] レビューメモ：例）「言葉の棚タブから購入します。買い切りで、購入すると全期間の言葉が
      読めるようになります。今日の一枚とウィジェットは購入の有無で変わりません。」

### 5. 税カテゴリ

App本体とは別に、App内課金にも指定が必要です。

- [ ] 既定の「App内課金（その他）」を選ぶ

### 6. ステータスを「送信準備完了」にする

1〜5 がすべて埋まると、ステータスが自動的に「送信準備完了」に変わります。

- [ ] ステータスが「送信準備完了」になっている

**この状態になって初めて Sandbox / TestFlight で商品が取得できます。**
反映に数時間かかることがあります。

### 7. アプリ本体と一緒に審査提出する

**初めての App内課金は単独で審査に出せません。**

- [ ] アプリのバージョンページを開く
- [ ] 「App内課金」セクションで `言葉の棚` を**今回のバージョンに紐づける**
- [ ] その状態で審査へ提出する

紐づけを忘れると、アプリ本体だけ審査に進み、課金は未承認のまま残ります。

## 審査用スクリーンショットの作り方

`docs/assets/appstore/iap-review-640x920.png` に用意済みです。撮り直す場合の手順:

1. Xcode から Wiseish スキームでシミュレータを起動する。スキームに `Wiseish.storekit` が
   紐づいているため、ASC への登録前でも `棚をひらく  ¥500` が価格付きで表示される
2. 「棚」タブを開いた状態で `xcrun simctl io booted screenshot out.png`
3. 640×920 へ加工する（iOS の App内課金審査用スクリーンショットの規定サイズ）

```bash
# 1206x2622 のシミュレータスクショを 640x920 にする例
sips -c 1734 1206 out.png --out iap.png    # 縦横比を 640:920 に合わせて中央を切り出す
sips -z 920 640 iap.png                     # 640x920 へ縮小
```

DEBUGビルドでは画面下部に「開発用・利用カウント」の行が出ます。この切り出し範囲なら
枠外になりますが、撮り直す際は**この行が写り込んでいないか確認**してください。

## 確認方法

新しい製品IDを含むビルドを TestFlight に上げてから、「棚」タブを開く。

| ボタンの表示 | 意味 |
| --- | --- |
| `棚をひらく  ¥500` | 商品の取得に成功している。正常 |
| `棚をひらく`（価格なし） | 商品が取得できていない。下の表を参照 |

TestFlight の購入は Sandbox 環境で処理され、**実際の請求は発生しません**。
非消耗型のため一度購入すると購入済み状態が残ります。未購入状態に戻すには
iPhone の「設定 > App Store > Sandboxアカウント」から購入履歴をリセットします。

## 商品が取得できないときの切り分け

`Product.products(for:)` は、存在しない製品IDを渡しても例外を投げず**空配列を返す**だけです。
そのため原因はアプリ側のログではなく、App Store Connect 側の状態で切り分けます。

| 確認する場所 | あるべき状態 |
| --- | --- |
| ビジネス > 契約 | 有料App契約が「有効」 |
| App内課金のステータス | 「送信準備完了」以上 |
| 審査に関する情報 | スクリーンショットが登録済み |
| 製品IDの綴り | `WiseishStore.shelfProductID` と完全一致 |
| TestFlight のビルド | 現在の製品IDを含むビルドか（古いビルドは旧IDを見にいく） |
| 反映待ち | 「送信準備完了」にしてから数時間経過したか |

アプリ側は、商品が取得できない場合に「いま棚をひらけません。時間をおいてお試しください。」と
表示します（`WiseishPurchaseState.unavailable`）。このメッセージが出ている場合は、
アプリの不具合ではなく上表のいずれかが未完了です。
